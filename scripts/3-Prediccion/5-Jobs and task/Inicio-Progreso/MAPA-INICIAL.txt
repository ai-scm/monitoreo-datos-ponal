PUNTO 3: INICIO Y EJECUCION DE TAREAS DE PREDICCION
Un solo archivo principal: mapear_inicio_progreso.py.
Usa ECS, STS y telemetria existente en CloudWatch. Solo lectura en AWS.

EJECUTAR EN CLOUDSHELL
  python3 mapear_inicio_progreso.py

Reemplazar primero la copia de CloudShell por la version actualizada.
No necesita ATHENA_OUTPUT_S3. No consulta, valida ni escribe S3 o DynamoDB.

ECS
Muestra arranque/espera desde creacion hasta inicio, parada o captura.
Muestra ejecucion desde startedAt hasta executionStoppedAt/stoppedAt o captura.
No inventa duracion final para STOPPED sin tiempo de parada interpretable.
No utiliza fecha objetivo de prediccion ni tiempos de DynamoDB.
Fechas ECS se calculan en UTC y se presentan tambien en hora Colombia.

FALLA: TaskFailedToStart, salida no cero de contenedor esencial confirmado,
health check UNHEALTHY o motivos explicitos de arranque/recursos tales como
OutOfMemoryError, CannotPullContainerError y ResourceInitializationError.
ExitCode 137 por si solo no prueba falta de memoria.
AVISO: paradas manuales/scheduler/Spot, errores de contenedor no esencial,
estados transitorios o informacion insuficiente. No hay umbrales por sigla.
STOPPED con esenciales en cero y sin otra evidencia de error puede ser OK.
RUNNING/OK significa sin error observado; no certifica avance ni prediccion valida.

LOGS
Lee logConfiguration de cada contenedor. Si usa awslogs y tiene grupo/prefijo,
consulta exclusivamente prefijo/contenedor/ID-tarea en su region configurada.
No mezcla streams de otras tareas. No habilita logs ni cambia configuracion.
Driver distinto, configuracion insuficiente o definicion inaccesible se informan.
Usa FilterLogEvents paginado, con limite y truncamiento explicitos.
Si se trunca, la muestra contiene los PRIMEROS eventos de la ventana; ampliar
--max-eventos o reducir --ventana-minutos para completar la lectura.

Cuenta eventos con nivel ERROR/FATAL/CRITICAL, encabezados Traceback y lineas
que empiezan con una clase Error/Exception. Cuenta retrying/reintentando.
Son indicios para revisar, clasificados AVISO; un error capturado o recuperado
no prueba que toda la tarea haya fallado. No se buscan palabras vagas como
error_rate=0. Tampoco se detectan todos los errores posibles de la aplicacion.
No se exportan mensajes completos ni trazas: solo conteos, categorias, referencias
al grupo/stream y etiquetas explicitas de avance. No se muestran overrides,
variables de entorno, comandos ni secretos de la definicion de tarea.

AVANCE REPORTADO
Los eventos JSON pueden contener etapa o stage (texto corto) y los contadores
enteros unidades_completadas y unidades_total, con 0 <= completadas <= total.
Ejemplo de evento que el monitor ya reconoce, si la aplicacion lo emite:
  {"stage":"prediciendo","unidades_completadas":3,"unidades_total":8}
El monitor NO agrega esos eventos a la aplicacion. Sin ellos, muestra
LOGS PRESENTES; sin avance explicito o NO VERIFICABLE. Una etiqueta de etapa
reportada no demuestra que siga avanzando ni que se haya completado el proceso.
Sin logs en la ventana no se deduce bloqueo, ni ausencia de logs historicos.

CPU Y MEMORIA
Busca CpuUtilized y MemoryUtilized en ECS/ContainerInsights con ClusterName y
TaskId exactos. Consulta las dimensiones completas descubiertas y excluye
series ContainerName. Nunca asigna el promedio del cluster o servicio a una tarea.
Muestra el ultimo promedio disponible de un minuto: CPU units y MB, no porcentaje.
Hora, maximo, dimensiones y muestras quedan en el detalle de metricas del CSV.
Solo lee las series existentes; no activa Container Insights. SIN DATOS significa
que no encontro puntos por tarea en la ventana, no consumo cero. Puede deberse a
configuracion o retraso de publicacion. El consumo no genera fallas por umbral.

COBERTURA Y SALIDA
Dos tablas compactas: ECS y telemetria. Los controles combinan evidencia ECS
y avisos por indicios en logs o lectura incompleta. Los CSV conservan tambien
estado_ecs_control y motivo_ecs para distinguirlos de los avisos de telemetria.
Local: salida/inicio_progreso/FECHA/HORA/tareas.csv y contexto.json.
Cada ejecucion conserva su propia captura local. --no-export desactiva archivos.
No es un historial continuo: no captura tareas/eventos desaparecidos entre lecturas.
No crea reglas EventBridge, alarmas, infraestructura ni notificaciones automaticas.

Lista desiredStatus RUNNING y STOPPED. PENDING aparece como lastStatus en tareas
con desiredStatus RUNNING; no se consulta desiredStatus=PENDING.
STOPPED visible es una captura reciente, no todo el historial de ejecuciones.
Busca sigla en el entorno efectivo de cada contenedor (definicion mas overrides
de ejecucion). Un override reemplaza la variable del mismo nombre exacto,
incluso si el nuevo valor es vacio. No conserva el valor anterior como evidencia.
No lee archivos de entorno externos ni valores inyectados desde secretos.
Tambien busca en etiquetas de tarea y parametros: variables con nombre
sigla/SIGLA_FISICA y CAD (confirmada en el entorno de las tareas), campos
sigla/siglas/SIGLA_FISICA dentro de payloads JSON o
literales de diccionario Python y argumentos --sigla METIB / --sigla=METIB.
No ejecuta comandos ni imprime sus valores completos. Si no se autoriza consultar
TAGS, reintenta DescribeTasks sin etiquetas y declara cobertura incompleta.
Una unica sigla explicita en esos parametros se muestra CONFIGURADA EN TAREA.
Varias siglas distintas se muestran MULTIPLES, sin atribucion unica. Se guardan
solo las siglas extraidas y tipos de fuente, nunca el payload original.
Tambien busca campos sigla en logs estructurados y marcas sigla: METIB o
sigla=METIB. Si solo aparece en logs, muestra SOLO REFERENCIAS / NO CONFIRMADA:
una mencion puede referirse a datos de otra unidad. CSV conserva las referencias.
No utiliza la familia, nombres del cluster compartido, letras mayusculas sueltas
ni etiquetas de la definicion compartida para atribuir una tarea a una sigla.
La busqueda en logs cubre solo la ventana/muestra consultada; una sigla informada
unicamente al iniciar hace varios dias podria no aparecer en esta captura.
No incluye el servicio SER continuo ni detecta solicitudes sin tarea creada.
Sin calendario esperado, cero tareas no prueba una falla.

Una denegacion o error de una fuente no elimina el diagnostico de las demas.
Truncamientos y errores AWS se informan como lectura incompleta, con exit 3.
Ausencia de series metricas no es un error AWS. Logs sin configurar son AVISO.
JSON completo indica consultas sin errores/truncamiento; ademas tiene el campo
telemetria_disponible_en_todas_las_tareas para distinguir disponibilidad real.
Exit 0 sin FALLA (puede haber AVISO), 1 FALLA, 2 argumentos, 3 lectura incompleta
/error AWS, 130 interrupcion. Interrumpir el script no detiene ninguna tarea ECS.

PERMISOS DE LECTURA
sts:GetCallerIdentity; ecs:DescribeClusters, ecs:ListTasks, ecs:DescribeTasks,
ecs:DescribeTaskDefinition; logs:FilterLogEvents para los grupos configurados;
cloudwatch:ListMetrics y cloudwatch:GetMetricStatistics.
ecs:ListTagsForResource puede ser necesario para incluir TAGS en DescribeTasks.
El script no crea ni modifica permisos. Si faltan, informa la fuente afectada.
